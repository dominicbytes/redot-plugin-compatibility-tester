# GitHub repository preparation

Intended repository: `https://github.com/dominicbytes/redot-plugin-compatibility-tester` with default branch `main` and MIT license.

Before remote creation:

1. Review `git status`, generated schemas, notices, workflows, and every retained blocker.
2. Run the complete quality and alpha release dry run in `docs/release/README.md`.
3. Confirm no `.artifacts`, local engines, caches, credentials, reports, or private source are tracked.
4. Create the empty GitHub repository without an autogenerated README/license/gitignore (these already exist).
5. Add the remote explicitly, push `main`, enable private vulnerability reporting, and require the Quality workflow for pull requests.
6. Keep the release workflow non-publishing until the owner separately approves a release and all claims match green gates.

Suggested commands are intentionally not executed here:

```console
git remote add origin https://github.com/dominicbytes/redot-plugin-compatibility-tester.git
git push -u origin main
```

Do not tag `v1.0.0`: the project remains `0.1.0` alpha until the remaining G-01/G-04/G-06, phase, and platform work is complete. The earlier engine, exact-control, containment, and optional Mono blockers are resolved locally, but that does not authorize publication.
